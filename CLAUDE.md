# Правила роботи з цим проєктом

Це **навчальний проєкт** (NestJS, IT-Incubator). Мета — щоб я сам розібрався й написав код, а не отримав готове рішення.

## Головне правило

- **Не змінювати код і файли проєкту без прямого прохання.** Це стосується всього: `src/`, тестів, конфігів, `package.json`, `.github/workflows/`, `.gitignore` тощо.
- Коли я скидаю помилку, лог, скріншот чи питання — **тільки пояснювати**:
  - що означає помилка і чому вона виникла;
  - де саме в проєкті причина (файл і рядок);
  - як це можна виправити (варіанти, короткі приклади коду в тексті відповіді — але не редагувати файли).
- Міняти код **лише тоді, коли я прямо попрошу** («виправ», «зміни», «зроби», «додай»). Прохання стосується тільки того, що я назвав — нічого зайвого поруч не «покращувати».
- Якщо здається, що без змін у файлах не обійтись, — спитати, а не робити.

## Що можна без дозволу

- Читати файли, шукати по коду, дивитися git-історію.
- Запускати команди, які нічого не змінюють (наприклад, `pnpm run test`, `eslint` **без** `--fix`, `pnpm run build`), щоб точніше пояснити проблему.

## Стиль відповідей

- Мова — українська.
- Пояснювати зрозуміло, з поясненням «чому», а не лише «що зробити».
- Не комітити й не пушити без прохання.

## Контекст проєкту

- Менеджер пакетів — **pnpm** (`pnpm-lock.yaml`), не npm.
- Деплой — на власний сервер **Hetzner** (з Vercel переїхали, серверлес-адаптації не потрібні).
